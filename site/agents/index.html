tisplay / agents

Agent quickstart

Start a session, inspect the screen, take one action, then inspect again. Use the installed CLI help and capability report for the target machine.

Start and inspect

tisplay capabilities --json
tisplay session start --json
tisplay screenshot --session SESSION_ID --out screen.png --json

Act and inspect again

tisplay click --session SESSION_ID --x 640 --y 360 --json
tisplay text --session SESSION_ID 'hello' --json
tisplay key --session SESSION_ID CTRL+L --json
tisplay screenshot --session SESSION_ID --out after.png --json

Use fresh screenshot coordinates in primary-display pixels. For a remote machine, add --host user@computer to each command; commands use SSH and open no listener port.

Use tisplay attach --session SESSION_ID --view-only to watch without acquiring input control. Start a fresh session after an upgrade; existing attached viewers and older sessions keep running.

Optional semantic tools on Linux

Tisplay can install the MIT-licensed Cua Driver v0.28.2 on demand. The CLI validates the Linux x86_64 or ARM64 archive against the checksum published with the upstream release. Install AT-SPI prerequisites such as at-spi2-core and libxi6 on Debian-based systems before using accessibility trees.

tisplay --host user@computer cua install
tisplay --host user@computer cua tools
tisplay --host user@computer cua describe get_window_state
tisplay --host user@computer cua call --session SESSION_ID list_windows
tisplay --host user@computer cua call --session SESSION_ID get_window_state \
  --args '{"pid":123,"window_id":456}' --out state.png
tisplay --host user@computer cua call --session SESSION_ID click \
  --args '{"pid":123,"window_id":456,"element_token":"…","snapshot_id":"s…"}'
tisplay --host user@computer cua mcp --session SESSION_ID

Use the element_token and snapshot_id returned by get_window_state. The Cua process is private to the Tisplay session and stops with it. --out saves screenshots on the machine running this CLI; image bytes are omitted from normal output. MCP is a persistent stdio stream over SSH, with no remote network listener. Semantic accessibility has passed on Linux X11; native labwc accessibility remains unverified and should be treated as unsupported until AT-SPI and the driver's desktop capabilities are present.

Display modes

Linux selects an available supported desktop. For sessions, --mode native-existing requires an existing native desktop, --mode native-headless may create an isolated labwc/D-Bus session, and --mode virtual starts Xvfb/XFCE. Check capabilities for the actual backend.

macOS uses the logged-in desktop and requires Screen Recording and Accessibility permissions.
